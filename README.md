# 두레이 AI 어시스턴트 (3차 버전 — 대시보드 추가)

트레이 아이콘 형태로 상주하면서, 두레이 채팅방에서 "@두레이봇 질문"을 감지해 클로드 코드로
답을 만들어 보내주는 프로그램입니다. 태스크/위키/메일/캘린더/드라이브 도구는
클로드가 답변할 때 함께 쓸 수 있도록 MCP 도구로 내장되어 있습니다.

사내 오픈소스 클로데이(Clauday, github.com/limtaewon/dooray-claude-gui-assistance)의
실제 설치/실행 방식을 참고해서, 이번 버전부터는 아래 세 가지가 클로데이와 거의 같은 방식으로 동작합니다.

- **토큰 입력**: 파일을 직접 편집하지 않고, 첫 실행 시 뜨는 화면에 입력합니다. 저장하면
  이 컴퓨터의 자격 증명 관리자(윈도우 Credential Manager)에 안전하게 보관됩니다.
  클로드 코드용 두레이 도구(MCP)도 가능하면 자격 증명 관리자에서 토큰을 직접 읽도록
  등록되어, 어떤 파일에도 토큰이 평문으로 남지 않습니다. (이 컴퓨터의 node가 자격 증명
  관리자를 읽지 못하는 특수한 환경에서만 예외적으로 클로드 설정 파일에 저장되며, 이 경우
  로그에 안내가 표시됩니다.)
- **채널별 작업 폴더 분리**: 채팅방(채널)마다 별도 폴더에서 클로드를 실행해서, 여러 방에서
  동시에 써도 대화 내용이 섞이지 않습니다.
- **최근 대화 맥락 전달**: 멘션이 오면 그 채팅방에서 프로그램 실행 후 오간 최근 대화도 같이
  넘겨서, "그거 어떻게 됐어?" 같은 맥락 있는 질문에도 답할 수 있습니다. (단, 두레이 API에는
  과거 메시지를 조회하는 기능 자체가 없어서, 프로그램이 켜져 있는 동안 실시간으로 지나간
  메시지만 기억합니다. 켜기 전 대화는 알 수 없습니다 — 이 부분은 클로데이와 다릅니다.)

## 다운로드 / 설치

[GitHub Releases](https://github.com/taegeunsin-web/Dooray-AI-/releases/latest) 에서 최신
설치 파일(`두레이 AI 어시스턴트 Setup x.x.x.exe`)을 받아서 실행하세요. 설치 마법사를 따라가면
시작 메뉴/바탕화면에 아이콘이 생기고, 그다음부터는 그 아이콘만 더블클릭하면 됩니다.

Windows가 "게시자를 알 수 없는 앱" 경고를 띄우면 "추가 정보" → "실행"을 누르면 됩니다
(정식 서명(코드사인) 인증서가 없어서 나오는 정상적인 경고입니다 — 클로데이도 동일합니다).

### 처음 켤 때 — 두 가지만 준비

1. **클로드 코드(Claude Code) 로그인** — 이 컴퓨터에 클로드 코드가 설치되고 로그인까지
   되어 있어야 메일 요약·채팅 답변 같은 AI 기능이 동작합니다. 앱 안 "가이드" 탭에 설치
   명령어와 순서가 그대로 안내되어 있습니다. Windows에서는 Git도 함께 설치하는 걸
   권장합니다 — 클로드 코드가 내부적으로 사용합니다
   ([Git 다운로드](https://git-scm.com/download/win)).
2. **두레이 API 토큰** — 두레이 로그인 후 우측 상단 프로필 → 개인 설정 → API 토큰에서
   발급. 캘린더까지 쓰려면 CalDAV 전용 비밀번호도 두레이 웹메일 → 환경설정 → IMAP
   화면에서 함께 준비하세요.

앱을 처음 켜면 뜨는 "설정" 화면에서 위 값을 입력하고 저장하면 끝입니다 (토큰은 이 컴퓨터의
OS 자격 증명 관리자에 안전하게 저장되고, 파일에는 남지 않습니다).

## 화면 구성 둘러보기

실행하면 "두레이 AI 어시스턴트" 대시보드 창이 자동으로 뜹니다. 창을 닫아도 프로그램은 트레이
아이콘으로 계속 상주하고, 트레이 메뉴의 "대시보드 열기"로 다시 열 수 있어요. **화면 위쪽 탭
하나로 모든 메뉴가 모여 있어요** (홈·채팅·채팅방·템플릿·캘린더·메일·사용량 + 오른쪽 끝에
가이드·설정·로그 아이콘). 오른쪽 위 해 모양 버튼으로 **밝은 화면/어두운 화면을 전환**할 수
있고, 고른 상태는 기억됩니다 (기본은 밝은 화면).

- (상단) **홈**: 첫 화면. 오늘 일정·저장된 메일·연결된 자동화 건수를 한눈에 보여주고,
  연결이 아직 안 끝났으면 "3단계면 연결 끝나요" 안내 카드가 떠서 뭘 해야 하는지 알려줌
  (3단계가 다 끝나면 이 카드는 자동으로 사라짐). 아래에 "바로 물어보기" 입력창이 있어서
  여기서 질문하면 채팅 탭으로 넘어가며 바로 답을 받고, 오른쪽에 연결 상태와 재연결/테스트 버튼이 있음
- (상단) **채팅**: 두레이 채팅방을 거치지 않고 여기서 바로 클로드에게 물어볼 수 있음.
  이전에 나눈 대화를 기억한 채로 이어서 물어볼 수 있고 "대화 초기화"로 새로 시작 가능
  (이 대화는 두레이에 저장되지 않고 프로그램을 껐다 켜면 사라짐)
- (상단) **채팅방**: 내가 참여 중인 모든 채팅방 목록과, 방마다 "누구나 호출 가능"
  여부를 토글로 켜고 끌 수 있음 (더 이상 config.json을 직접 편집할 필요 없음). "기록 저장"은
  기본이 켜짐이라 모든 방의 대화가 자동으로 파일에 쌓이고, 저장을 원하지 않는 방만 토글을
  꺼주면 됨 (끈 상태는 설정 파일에 계속 남아서 프로그램을 껐다 켜도 유지됨). 아래 검색창에서
  검색어만 입력하면 "기록 저장"이 켜진 모든 채팅방을 한 번에 뒤져서 찾아줌 — 어떤 채팅방에서
  그 말을 했는지 기억이 안 날 때를 위한 용도 (토글을 켜기 전 대화는 저장 안 됨 — 두레이 API
  자체에 과거 메시지 조회가 없어서 어쩔 수 없는 한계)
- (상단) **템플릿**: 프로젝트를 고르면 그 프로젝트의 업무 템플릿 목록이 나오고, 템플릿 이름을
  클릭하면 실제 제목/내용 미리보기와 서식이 적용된 미리보기(굵게/목록/체크박스/색상)가 함께
  나와서 고쳐서 바로 업무로 만들 수 있음. 같은 화면
  아래에 "채팅방 자동 연결" 영역도 있어서, 채팅방을 프로젝트+템플릿과 연결해두면 그 방에서
  "@호출단어 태스크 만들어줘"라고 부를 때 최근 대화 내용을 보고 템플릿을 채워서 자동으로
  업무를 만들어줌. 확실하지 않은 항목(개수, URL, 소재유형 체크박스 등)은 추측하지 않고
  비워두니, 만든 후 두레이에서 한 번 확인해주세요. 업무가 만들어지면 채팅방에 클릭해서
  바로 이동할 수 있는 업무 링크와 "기획안·상세 파일은 두레이에서 직접 첨부해주세요" 안내가
  함께 전송됨 (두레이 메신저 API는 채팅에 파일을 첨부해서 보내는 기능 자체가 없어서, 채팅에
  공유된 파일을 자동으로 업무에 옮겨 붙이는 건 불가능함). 이 연결 화면에서 아래 항목들을 미리
  고정해둘 수 있음 (두레이 템플릿 자체는 건드리지 않고, 이 프로그램 안에서만 저장됨):
  - **제목 접두사**: 예) `[LG유플러스]` 를 적어두면 제목 맨 앞에 항상 붙고, 뒤에는
    요청 내용에 맞는 문구(예: "브랜드검색 소재 제작 요청")를 AI가 자동으로 붙여줌
  - **기본 담당자**: 이름으로 검색해서 한 명 지정. 단, 채팅방에서 요청자가 아닌 다른
    사람이 "확인했습니다", "전달드리겠습니다" 처럼 확인 답장을 남겼다면 그 사람이 먼저
    담당자로 자동 지정되고, 그런 답장이 없을 때만 여기서 지정한 사람이 담당자가 됨
  - **참고**: 이름으로 검색해서 여러 명 지정 가능
  - **태그**: 프로젝트를 고르면 그 프로젝트의 태그 목록이 체크박스로 나오고, 체크한
    태그가 항상 붙음
- (상단) **캘린더**: 내 캘린더의 일정을 조회하고 새 일정을 등록할 수 있음 (새 일정 등록 시
  저장할 캘린더를 따로 지정 가능). (참고: 두레이가 프로젝트/팀 캘린더는 아직 API로
  제공하지 않아서, 지금은 "내 캘린더"만 나옴 — 나중에 두레이가 열어주면 추가할 예정)
- (상단) **메일**: "메일함"(기본으로 보이는 화면)과 "발신자별 정리"(작은 탭) 두 가지로
  이루어져 있음. 프로그램이 켜져 있는 동안 1분마다 새 메일을 자동 저장하고, 시작할 때도
  한 번 먼저 따라잡기 때문에 꺼져있던 동안 온 메일도(최근 2주 이내라면) 놓치지 않음.
  "⚙ 저장·알림" 버튼을 누르면 "이 폴더만 저장하기"와 "메일 도착 알림" 설정이 열림 (자주
  쓰지 않는 설정이라 평소엔 접혀 있음).
  - **메일함** (기본 탭): 저장된 메일을 두레이 웹메일을 열지 않고 여기서 바로 읽는 화면.
    **왼쪽 목록 / 가운데 본문 / 오른쪽 "할 일" 3분할 구조**라, 메일을 읽으면서 내가 처리해야
    할 것들을 동시에 볼 수 있음. 읽는 영역은 흰 배경이라 두레이 원본 메일 서식이 그대로
    깨지지 않고 보임. 두레이 API는 본문 미리보기 일부만 줘서, 설정에서 "메일 전문
    가져오기(IMAP)"를 켜면 메일을 여는 순간 IMAP으로 원문 전체를 자동으로 가져와 저장함
    (메일당 1회, 두레이 웹메일 설정에서 "IMAP 사용"을 먼저 켜야 하고 메일 비밀번호는 자격
    증명 관리자에 보관됨. 실패하면 "재조회" 버튼으로 다시 시도 가능). 메일을 열면 AI 요약도
    함께 나오고(`* ` 항목별로 줄바꿈된 상세 요약, [요청] 표시 포함), "다시 요약하기"로
    언제든 새로 만들 수 있음
  - **할 일 (요청 모아보기)**: 오른쪽 레일에 항상 떠 있음. 폴더를 고르면 그 폴더의 메일
    요약 중 [요청]으로 표시된 항목이 모두 모여서 완료 체크로 관리할 수 있음 (체크 상태는
    저장되어 껐다 켜도 유지됨). 각 항목에는 어느 메일에서 나온 건지 보낸사람이 링크로
    달려 있어 바로 원문을 열어볼 수 있음. **채팅방으로 보낸 도착 알림 요약도 여기에 자동으로
    반영됨** — 예전에는 "발신자별 정리" 화면을 직접 열어봐야만 할 일이 생겼는데, 이제는
    요약이 만들어진 메일이면 어디서 만들어졌든 전부 할 일 목록에 올라옴
  - **발신자별 정리** (작은 탭): 폴더를 고르면 그 안의 메일을 "사람별" 또는 "제목별(같은
    답장 스레드끼리)"로 자동으로 묶어서 왼쪽 목록에 보여주고 — 즐겨찾기(★)한 항목이
    맨 위, 그다음 메일 많은 순 — 항목을 누르면 오른쪽에 메일별로 "제목(클릭하면 원문으로
    이동) + 그 메일의 AI 요약"이 각각 따로 나옴 (어떤 요약이 어느 메일 건지 한눈에 보임).
    요약 결과는 파일로 저장돼서 껐다 켜도 유지되고, 그 그룹에 새 메일이 왔을 때만 자동으로
    다시 요약함 ("다시 요약하기"로 강제 갱신 가능). 보낸사람/제목/받은 기간 필터도 지원.
    요약에서 내가 직접 처리해야 하는 항목은 [요청] 표시가 붙고(설정에 저장된 내 이름
    기준으로 AI가 판단), 위 "할 일" 레일에 모여서 완료 체크로 관리됨. "메일 도착 알림"에서
    폴더와 채팅방을 지정해두면, 그 폴더로 새 메일이 올 때마다 상세한 AI 요약과 원문 바로가기
    링크를 그 채팅방으로 자동 전송함 (밀린 메일 여러 건이 한꺼번에 확인되면 묶음 메시지 하나로 보냄)
  - 메일함/발신자별 정리/메일 도착 알림, 4곳 모두 같은 요약 로직을 공유해서 형식이
    항상 일관되고, 한 번 요약한 메일은 다른 화면에서도 재사용되어 AI 호출(토큰)이
    중복으로 낭비되지 않음
- (상단) **사용량**: 이 프로그램이 클로드를 부를 때마다(메일 요약/채팅/@멘션/자동 업무 생성
  등) 쌓이는 사용 이력을 보여주는 대시보드. 총 비용(달러)·토큰·API 호출 수·캐시 히트율·
  활성 일수 카드, 일별 추이, 모델별 비율, 시간대별 사용 패턴, 기능별 호출 횟수를 24시간/7일/
  30일 기준으로 토글해서 볼 수 있음. 사내 오픈소스 클로데이의 "사용량 대시보드"를 참고해서
  같은 항목을 우리 프로그램 구조에 맞게 새로 구현함. ⚠️ 구독 요금제(Pro/Max)의 "이번 주
  남은 한도(%)" 는 클로드 서버에만 있는 정보라 여기서 확인할 수 없음 — 이건 클로드
  데스크탑 앱/대화창의 `/usage`에서만 확인 가능. 여기 보이는 건 "지금까지 실제로 쓴 양"의
  이력이며, 비용은 클로드가 매 호출마다 공식으로 알려주는 값(`--output-format json`)을
  그대로 기록한 것이라 정확함 (원화 환산은 환율 문제로 넣지 않음)
- (우측 상단) 항상 작은 상태 점(초록/노랑/빨강)과 연결 문구가 떠 있고, 클릭하면 홈으로 이동함
- (상단 오른쪽 아이콘) **가이드**: 처음 쓰시는 분들을 위한 준비 안내 (컴퓨터 사전 준비부터
  클로드 코드 로그인/폴더 신뢰 확인, 프로그램 설치, 토큰/도메인 확인, 설정 저장, 실제
  사용까지 7단계로 정리되어 있음)
- (상단 오른쪽 아이콘) **설정**: 두레이 주소(예: `nhnent.dooray.com`), API 토큰(두레이 로그인 후
  우측 상단 프로필 → 개인 설정 → API 토큰에서 발급), 채팅 호출 단어(기본값 `두레이봇`),
  컴퓨터 로그인 시 자동 실행 여부, 자동 생성 업무 인사말에 쓸 내 정보(팀명/이름 — 메일
  요약의 [요청] 판단에도 사용됨), 그리고 "저장된 모든 정보 초기화"(테스트용 — 이 프로그램이
  만든 토큰/설정/기록/MCP 등록만 지우며, 클로드 앱 자체나 Node.js는 건드리지 않음)
- (상단 오른쪽 아이콘) **로그**: 최근 활동 기록 (문제 생기면 여기 내용을 캡처해서 보내주시면 됩니다)

오른쪽 위 설정 아이콘에서 두레이 주소/토큰을 입력하고 저장하면 자동으로 연결을 시작합니다
(처음이라면 "가이드" 탭을 먼저 봐주세요). 연결되면 두레이 채팅방에 "@두레이봇 이번 주 태스크
알려줘" 같은 걸 보내보세요.

### 회의실 예약은 지원하지 않음

한때 두레이의 "자원예약" API(`/reservation/v1/...`)로 캘린더 탭 회의실 조회/채팅 회의실 예약
기능을 만들었었지만, 실제 브라우저 네트워크 요청을 확인해본 결과 우리 조직은 회의실 예약을
두레이가 아니라 완전히 별도인 사내 시스템 "왓츠업"(whatsup.nhnent.com)으로 처리하고
있었습니다. 두레이 공개 API로는 애초에 접근할 수 없는 영역이라 (403 AUTH_FORBIDDEN_ACL_
SERVICE_ERROR), 이 기능은 되돌렸습니다. 회의실 예약은 왓츠업에서 직접 진행해주세요.

### 채팅방을 처음 쓸 때 한 가지 주의할 점

채널마다 별도 작업 폴더(`~/Dooray-Assistant-Workspaces/agent/{채널ID}/`)를 쓰는데, 클로드
코드 입장에서는 "한 번도 열어본 적 없는 폴더"라 처음에는 폴더를 신뢰하는지 확인하는 절차가
필요합니다. 이 절차가 자동화 모드(백그라운드 실행)에서는 화면에 뜨지 않고 그냥 응답이 안
오는 것처럼 보일 수 있어요. 만약 어떤 채팅방에서 유독 응답이 안 온다면:

1. 대시보드 "가이드" 탭의 **"클로드 확인 창 열기"** 버튼을 누릅니다 (터미널을 직접 열 필요 없음 —
   처음 설정을 저장할 때도 이 창이 자동으로 한 번 뜹니다).
2. 뜬 창에서 "Yes, I trust this folder"를 선택하고 창을 닫습니다.

대부분의 경우 이미 한 번 다른 폴더에서 신뢰 절차를 거쳤다면 새 채널 폴더에서도 문제없이
동작하지만, 혹시 특정 방에서만 응답이 안 온다면 이 부분이 원인일 수 있습니다.

    mentionBot.js               <- "@두레이봇" 감지 + 채널별 작업폴더 + 최근 대화 맥락 + 클로드 호출
    claudeResolver.js            <- 클로드 실행 파일 자동 탐색 (PATH 미등록/npm 설치 대응) + 신뢰 확인 창 띄우기
    ensureMcp.js                <- claude mcp add 자동 등록
    preload.js                  <- 대시보드 화면과 프로그램을 안전하게 연결하는 다리
    dashboardWindow.js          <- 대시보드 창을 띄우는 코드
    doorayService.js            <- 프로젝트/템플릿/캘린더 조회 + 템플릿으로 업무 생성

    taskAutomation.js            <- 채팅에서 "태스크 만들어줘" 감지 + AI로 템플릿 채워서 업무 생성 (대화에 언급된 만기일도 자동 인식)
    chatHistoryStore.js          <- 채팅방 대화를 파일로 저장(기본 켜짐, 방별로 끌 수 있음) + 전체 채팅방 통합 검색
    channelFileStore.js          <- 채팅방에 올라온 파일(첨부파일) 메타데이터를 실시간으로 붙잡아 저장

    mailSummaryCache.js          <- 메일 단건/그룹별 AI 요약 결과 저장(껐다 켜도 유지) + 요청 완료 체크 저장
    usageStore.js                <- 클로드 호출마다 비용/토큰 기록 저장 + 사용량 대시보드용 통계 계산

## 화면 디자인 (2026-07 리디자인)

화면은 "Industry"라는 이름의 디자인 규칙을 따릅니다 — 밝은 회색 배경 위에 steel-blue 강조색,
**정사각 모서리(둥근 모서리 없음)**, 1px 얇은 테두리, 투명한 배경의 카드, 그리고 강조색으로 꽉 채운
요소는 기본 버튼 하나뿐입니다. 주요 카드 모서리에는 설계도면 느낌의 `+` 표시(등록 마크)가 붙습니다.

새 화면이나 카드를 추가할 때는 `dashboard.html` 맨 위 `<style>`의 `:root` 토큰과 공통 클래스
(`.card` `.btn` `.input` `.tag` `.table` `.seg`/`.subtab` `.blueprint`)를 그대로 쓰면 톤이 자동으로
맞춰집니다. **색상 값을 코드에 직접 적지 말고 항상 `var(--color-...)` 토큰을 쓰세요** — 그래야
라이트/다크 전환이 정상 동작합니다. (예외: 메일 본문 `.mailboxBody`와 템플릿 미리보기
`.tplRenderedPreview`는 두레이 원본 HTML 서식을 보존해야 해서 테마와 무관하게 항상 흰 배경입니다.)

글꼴은 Barlow(영문·숫자) + Pretendard(한글)를 우선 쓰되, 설치되어 있지 않으면 시스템 기본 글꼴로
자동 대체됩니다. 사내망에서 외부 폰트 CDN이 막힐 수 있어 웹폰트를 따로 불러오지는 않습니다 —
더 좋은 글꼴을 쓰고 싶다면 Pretendard를 컴퓨터에 설치하면 자동으로 적용됩니다.

## 채팅 첨부파일 → 드라이브 이동 (2026-07 갱신)

이전 버전 README에는 "채팅 첨부파일 다운로드는 불가능"이라고 되어 있었는데, 실제 소켓
이벤트 원본을 직접 로그로 찍어서 확인해보니 파일 업로드 이벤트(`content.type === 4`)에
`content.file = {id, fileName, fileSize, mimeType, ...}` 메타데이터가 들어있는 것을
발견했고, 이를 이용해 실제로 다운로드까지 성공했습니다 (문서에 없는 주소를 추측해서 시도한
것이라 계속 될 거라는 보장은 없지만, 최소 한 번은 실제로 확인됨).

- **채팅방에 올라온 파일 목록 확인 + 다운로드**: 프로그램이 켜져 있는 동안 채팅방에 올라온
  파일의 메타데이터를 저장해두고(`~/Dooray-Assistant-Workspaces/chat-history/{채널ID}.files.jsonl`),
  채팅으로 "이 채팅방에 올라온 파일 찾아줘" 라고 하면 목록을 찾아주고, "다운로드해줘"라고
  하면 실제로 이 컴퓨터에 저장까지 됨 (`dooray_list_channel_files` / `dooray_download_channel_file`
  MCP 도구)
- **두레이 드라이브 파일 다운로드**도 같은 방식(경로만 반환, 내용은 AI 컨텍스트에 안 실림)으로
  가능 (`dooray_download_drive_file`)
- **구글 드라이브까지 자동으로 옮기기는 파일 크기에 따라 다름** — 지금 연결된 구글 드라이브
  연동(클로드 코드 계정에 이미 붙어있는 외부 연동, 이 프로그램이 만든 게 아님)은 파일 경로가
  아니라 내용 전체를 텍스트로 받아야 저장하는 방식이라, 수백 KB 이하 텍스트류는 자동으로
  올라가지만 수 MB 이상 파일(엑셀 리포트 등)은 토큰 초과로 사실상 실패함. 큰 파일까지 자동화
  하려면 이 프로그램 자체에 구글 OAuth 연동을 새로 붙여서 "경로만 넘기면 서버로 직접
  올리는" 업로드 도구를 만들어야 함 (다음 버전 후보). 지금 당장은 큰 파일은 두레이 공유링크로
  대신 전달하거나, 다운로드된 로컬 파일을 사용자가 직접 구글 드라이브에 올리는 방식을 사용

- 코드사인 인증서 적용 (지금은 실행 시 "알 수 없는 게시자" 경고가 뜸)
- 깃허브 액션으로 릴리즈 자동 빌드 (지금은 수동 — 클로데이 방식 참고, 팀 규모가 커지면 도입 후보)

## 개발자용

일반 사용자는 위 "다운로드 / 설치"만 보면 되고, 아래는 이 프로젝트를 고치거나 새 버전을
빌드할 사람을 위한 안내입니다.

```
npm install     # postinstall에서 keytar 네이티브 모듈 자동 리빌드
npm start       # 개발 모드로 바로 실행
npm run dist    # 배포용 실행 파일 빌드 → dist/ 폴더에 설치형(Setup.exe)·포터블 exe 둘 다 생성
```

(`실행.bat`을 더블클릭하면 터미널 없이도 `npm install` + `npm start`를 자동으로 해줍니다.
`설치파일_만들기.bat`은 `npm run dist`를 대신 실행해줍니다. 둘 다 로컬 편의 스크립트라
저장소에는 포함하지 않았습니다.)

미리 준비해야 할 것:

- 이 컴퓨터에 Node.js와 클로드 코드(claude)가 설치되어 있고, 클로드 로그인이 되어 있어야 합니다.
  (PATH 등록이 안 되어 있어도 프로그램이 흔한 설치 위치를 자동으로 찾아서 실행합니다.)
- **Git도 설치되어 있어야 합니다.** 윈도우에서 클로드 코드는 내부적으로 Git Bash를 사용해서,
  Git이 없으면 클로드 코드 자체가 정상 동작하지 않을 수 있습니다.
- 첫 실행 시 `claude mcp add`가 자동으로 실행되어 두레이 도구를 등록합니다
  (실패하면 트레이 메뉴 로그에 이유가 표시됩니다).
- keytar(토큰 보관용 라이브러리)는 네이티브 모듈이라 `npm install` 후 자동으로
  `electron-rebuild`가 한 번 더 돌아갑니다 (시간이 조금 더 걸릴 수 있어요, 정상입니다).

### 릴리즈 (새 버전 배포)

클로데이는 태그를 푸시하면 깃허브 액션이 자동으로 빌드해서 Releases에 올려주지만, 지금은
팀 규모상 그 정도까지는 필요 없어서 수동으로 진행합니다.

1. `package.json`의 `version` 값을 올립니다.
2. `npm run dist`로 빌드합니다 (몇 분 걸릴 수 있음).
3. 깃허브 저장소 → **Releases** → **Draft a new release** → 태그 입력(예: `v0.2.0`) →
   `dist` 폴더의 `두레이 AI 어시스턴트 Setup x.x.x.exe`를 끌어다 놓기 → **Publish release**.
4. 이미 설치되어 있는 사용자는 프로그램을 켤 때마다 자동으로 새 버전이 있는지 확인해서
   백그라운드로 받아두고, 재시작하면 반영됩니다 (**설치형 버전만 해당** — 포터블 exe는
   electron-updater가 자동 설치를 지원하지 않아 대상이 아닙니다).
